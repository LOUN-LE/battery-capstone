# 팀 팩 입력 규격과 셀 환산

기준일: 2026-11-09. 원본은 사용자가 제공한 `raw_input.csv`와 `metadata.json`이다. `bayesian prepare-input`은 두 파일과 명시적인 팩 설정을 읽어 입력을 검사하고, 원본의 시간·전류 부호를 유지한 셀 환산 자료를 만든다.

## 입력 열

| 열 | 의미와 단위 | 처리 |
| --- | --- | --- |
| `vehicle_id` | 차량 식별자 | 그대로 보존 |
| `cycle_id` | 기록된 운행 구분 ID | 차량과 함께 그룹을 구분; EFC로 해석하지 않음 |
| `timestamp_s` | 누적 배터리 시뮬레이션 시간, 초 | 분·UTC로 변환하지 않음 |
| `voltage_v` | 전체 팩 전압, V | 원본 보존; 대표 셀 전압을 별도 열에 추가 |
| `current_a` | 전체 팩 전류, A | 방전 양수, 충전·회생 음수 유지 |
| `temperature_c` | `module_01_temperature_c`, °C | 고정 모듈 센서값으로 보존; 셀 코어 온도로 변경하지 않음 |

메타데이터의 schema는 `pack_raw_six_v1`, revision은 2, basis는 `whole_pack`이다. 완료 여부는 ID의 크기가 아닌 `status`와 `cycle_protocol`에 근거한다. 제공 자료는 완료된 운행 5개를 포함하지만 완전 충방전 5회라는 뜻은 아니다.

## 팩 구성과 변환

직·병렬 수는 제공 메타데이터에 없다. `configs/team_pack_108s32p.json`은 M50T ROM 5회 결과보고서에 기록된 **108S32P** 구성을 명시적으로 적용한다. 이전 README의 108S2P 문구는 이 입력 기준에 맞게 수정했다.

- 대표 셀 전압: `cell_voltage_v = voltage_v / 108`
- 대표 셀 전류: `cell_current_a = current_a / 32`
- 그룹 경과 시간: `elapsed_s = timestamp_s - 해당 vehicle_id·cycle_id의 첫 timestamp_s`

전압은 직렬 셀의 평균, 전류는 병렬 셀의 균등 분담을 가정한다. 따라서 환산은 셀별 편차·전류 분배·온도 분포를 복원하지 않는다. 이 값이 OKane2022 또는 보정된 M50T 모델에 곧바로 적합하다는 의미도 아니다.

## 시간과 경계행

원자료의 가변 표본 간격을 그대로 유지한다. 1초로 재표본화하거나 긴 간격을 영전류로 채우지 않는다. 동일 그룹 내부의 시각은 엄격히 증가해야 하며, 다른 cycle의 끝과 시작이 같은 시각인 경계행은 그룹별로 보존한다. 그룹을 합친 뒤 중복 시각을 무조건 삭제해서는 안 된다.

입력 준비 단계는 임의의 셀 전압 범위로 행을 제거하지 않는다. 팩 전압에 과거 셀 전압 필터를 적용하거나, 환산 결과를 이전 학습 데이터의 전압 범위에 맞추기 위해 잘라내지 않는다.

전류 적분과 `PackCycle.current_intervals()`는 각 구간의 오른쪽 끝 표본을 그 구간의 전류로 사용하는 방식을 명시한다. 이는 제공 자료의 Ah 누계와 비교하는 재구성 규칙이며, 표본 사이의 실제 전류를 관측했다는 뜻은 아니다. 서로 다른 cycle 사이에는 적분 구간을 만들지 않는다. 음전류는 충전과 회생이 섞여 있으므로 6열 자료만으로 두 활동을 분리하지 않는다.

## 실행과 결과

저장소 `repo`에서 기존 가상환경으로 실행한다. 출력은 새 폴더를 지정한다.

```powershell
& ..\.venv\Scripts\python.exe -m bayesian prepare-input --csv 'data/raw_input.csv' --metadata 'data/metadata.json' --pack-config configs/team_pack_108s32p.json --output ..\work\team_input_20261109
```

| 파일 | 내용 |
| --- | --- |
| `normalized_cell_input.csv` | 원본 팩 6열과 대표 셀 전압·전류, 그룹별 경과 시간 |
| `input_report.json` | 원본·설정 해시, 행 수와 범위, 경계행 수, cycle별 Ah와 메타데이터 누계의 차이, 변환 설정 및 적용 범위 |

원본 CSV와 메타데이터를 수정하지 않는다. 검증 결과는 실제 실행이 끝난 뒤 생성된 보고서로 확인한다.

## 제공 파일로 확인한 결과

2026-11-09 실제 입력 준비 실행과 별도 행 대조를 완료했다. 142,817행의 원래 숫자값, 전압÷108, 전류÷32 및 cycle별 경과 시간이 모두 일치했다. 동일한 경계 시각 4개를 보존했고, 입력 파일 해시도 변하지 않았다. 오른쪽 끝 전류로 적분한 Ah와 메타데이터 누계의 최대 차이는 5.173×10⁻¹²Ah였다.

출력과 확인 근거는 `outputs/input_alignment_20261109/`의 `normalized_cell_input.csv`, `input_report.json`, `verification.json`이다. 입력 전용 12개(`bayesian/test_pack_input.py`), 기존 주행 5개, 최적화 17개를 합쳐 관련 검사 34개를 통과했다. 전체 저장소 회귀 검사나 물리 성능 검증을 수행했다는 뜻은 아니다.

이 입력 준비 단계에서는 모델 시뮬레이션을 실행하지 않았다. 이후 아래의 짧은 SPMe 재현을 별도로 완료했다. Wh 누계를 정확히 재구성했다고 주장하지 않으며, CSV의 고정 모듈 센서 온도와 메타데이터 내부의 최대 배터리 온도도 서로 다른 지표다.

## 짧은 SPMe 재현 완료 — 2026-11-09

`bayesian replay-input`은 원자료 검증→팩·셀 환산→구간 선택→실제 SPMe 계산→`result.json` 저장까지 수행한다. 원자료와 메타데이터를 직접 입력하며 앞 단계의 변환 CSV를 중복 변환하지 않는다.

```powershell
& ..\.venv\Scripts\python.exe -m bayesian replay-input --csv 'data/raw_input.csv' --metadata 'data/metadata.json' --pack-config configs/team_pack_108s32p.json --cycle-id 1 --duration-s 300 --output ..\work\team_replay_20261109
```

| 항목 | 실제 실행 조건·결과 |
| --- | --- |
| 입력 구간 | cycle 1 시작부터 300초 이내의 마지막 실제 표본까지; 318행·317구간 |
| 실제 종료 시간 | 299.542407256642초; 재표본화 없음 |
| 모델 | 기존 OKane2022 등온 SPMe, SEI·일부 가역적 리튬 도금 설정 유지 |
| 초기 상태 | 메타데이터 BMS SOC 80%를 균일한 새 모델 SOC 0.8로 대응시킨 가정 |
| 온도 | 첫 module_01 센서값 20°C로 고정; 원자료 센서는 20~20.07256°C |
| 전류 적용 | 각 구간 오른쪽 끝의 전류÷32를 일정하게 적용, 이전 미분 상태 유지 |
| 솔버 | PyBaMM 26.8.0.0, IDAKLU, rtol 1e-8·atol 1e-10 |
| 전 구간 완주 | 299.542407초 완료; 입력 전류·상태 연속성 검사 통과 |
| 전체 전하 잔차 | −5.3603×10⁻¹⁶Ah; 검사 기준 1e-7Ah |
| 셀 전압 RMSE / 최대 절대 오차 | 19.876mV / 24.075mV |
| 결과 위치 | `outputs/spme_replay_20261109_v2/result.json` |

전압 비교는 다음 전류로 바뀌기 전의 구간 끝 값을 사용한다. 첫 원자료의 전류는 0A지만 첫 적용 구간은 다음 행 전류를 사용하므로, 첫 행은 전압 오차 평가에서 제외한다. 결과에 각 구간의 관측 전압과 모델 전압을 함께 저장했다.

동일 조건으로 반복한 `outputs/spme_replay_20261109_repeat/result.json`의 317개 구간 결과와 요약이 첫 성공 결과와 완전히 일치했다. 원본 CSV와 저장된 모든 구간 및 소스 해시를 독립 대조한 근거는 성공 결과 폴더의 `verification.json`이다. 재현 8개·입력 12개·주행 5개·BO 17개를 함께 실행한 관련 검사 42개가 6.196초에 통과했다.

연결 실행과 수치 검사가 완료된 결과다. 원자료는 팀 ROM 출력이며, 균일 초기 상태·모듈 온도 대리값·전류 균등 분담 가정의 실차 적합성을 입증하지 않는다. C 셀 전용 보정 초기 상태를 이식하거나 전압에 맞춰 초기 SOC를 조정하지 않았다. SOH·잔여 수명은 `null`, 물리 모델 적합성·수명 검증은 `false`로 남긴다.

첫 연결 시도에서 미분 상태 길이를 원 모델에서 찾는 오류가 발생했으며, 이산화된 모델의 길이를 사용하도록 수정했다. 실패 기록은 `outputs/spme_replay_20261109/result.json`에 보존돼 있다. 성공 결과와 구분한다.

## 다음 연결에 필요한 정보

`replay-input --thermal-mode lumped --ambient-temperature-c 20`으로 SPMe의 전기화학 모델에 셀 평균 온도 방정식을 결합할 수 있다. 첫 모듈 센서값을 초기 셀 평균 온도의 대리값으로 쓰고, 주변 온도는 별도 입력으로 고정한다. 결과에는 모델의 평균 온도와 ROM 모듈 센서값을 각각 기록한다. 20°C는 실행 예시의 경계조건이다.

`replay-input --cell-calibration m50-c-joint-v3`는 25°C C셀 RPT0에서 동결한 전극 활성물질 분율과 리튬 재고를 선택한다. 팀 입력의 초기 BMS SOC에 맞춰 농도를 새로 계산한다. RPT0용 C셀 휴지 상태는 그 실험을 재현할 때 사용한다. 선택한 보정의 출처, 적용값, 초기 리튬 재고 검사를 결과 JSON에서 확인할 수 있다. 옵션을 생략하면 기본 파라미터를 사용한다.

`driving --csv`는 운전자, 주행 ID, 경로, 방향, 교통, 거리, UTC 오프셋을 포함한 시작 시각, 동일한 계산 셀 기준을 요구한다. 현재 6열 자료에는 이 정보가 없으므로 가상의 값을 채워 GP 학습 자료로 만들지 않는다. 특히 `timestamp_s`는 실제 날짜가 아니고 `cycle_id`는 단일 주행의 식별자가 아니다.

현재 완료 범위는 입력 검사·대표 셀 환산·명시된 가정 아래의 짧은 SPMe 재현이다. 모델 물성·초기 상태·온도 가정의 독립 적합성 평가와 더 긴 운행 구간 검증, GP에 필요한 반복 주행 메타데이터 확보가 남아 있다. 팀원의 학습 모델용 특징 추출과 실제 전처리 실행 여부도 별도로 검증한다.
